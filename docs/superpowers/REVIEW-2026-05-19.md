# Code Review — 2026-05-19

Goal of the package (per README): **a monorepo for managing multiple isolated AI provider accounts (Claude / Codex / Gemini / OpenCode), routed through `cliproxyapi`, exposed as a unified chat API + headless/styled Vue surface + Litestar HTTP backend.**

Findings are ordered by impact on that goal.

---

## 1. Static-model drift is the dominant bug class — fix the architecture, not the list

**Evidence:** "Static model lists out of sync with cliproxyapi" is fixed in `0.3.9`, refined in `0.3.10` (live discovery added), and patched again in `0.3.12` (codex local cache, claude OAuth via keychain, direct `/v1/models`). Every minor release in 2026 has touched this surface.

**Today:** each backend ships a hardcoded `_STATIC` model list (`claude.py:list_models`, `codex.py:455`, `gemini.py:404`, `opencode.py:300`) that drifts every time upstream cliproxyapi adds/removes a mapping.

**Recommendation:**
- Persist the live `/v1/models` result to `~/.ai-accounts/models_cache.json` whenever cliproxy answers.
- Prefer cached-live over static everywhere, with a freshness TTL.
- Move the four static lists into one `models_fallback.toml` data file so updates are a one-line diff, not four-file Python edits.

## 2. Backend duplication — ~1000 LOC of near-identical methods

**Evidence:** `claude.py` 840 LOC, `codex.py` 740, `gemini.py` 584, `opencode.py` 451. All four implement the same shape: `detect → --version`, `validate`, `list_models` (cliproxy live → static fallback), `chat` (delegate `_chat_via_cliproxy` when credential is empty, else direct HTTP/SSE), `get_usage`, `pty`.

**Recommendation:** introduce `backends/_base.py` with a `CliProxyBackend` mixin providing:
- `_detect_via_version(cli_name)`,
- `_list_models_cliproxy_first(provider, static)`,
- `_chat_openai_style(url, body, headers)` (claude.py:700-770 ≈ codex.py:680-740 ≈ gemini.py:520-580 are copy-paste with three substitutions).

The `BackendProtocol` (`protocols/backend.py`) is already clean — no breaking changes.

## 3. ChatStreamEvent wire shape is leaky — fix at the source

**Evidence:** `chat_send.py` (litestar) has a comment block + rename (`text → payload`) at the SSE boundary because single-mode `ChatDelta` uses `text` while All/Compound `AllModeEvent` and frontend `useSmartChat` use `payload`. Bug fixed in 0.3.9.

**Recommendation:** unify on `payload` inside `services/chat_orchestrator.py` (`ChatDelta`), then delete the rename shim in `chat_send.py:90-110`. One struct, one name — eliminates the whole class of "undefinedundefined" regressions.

## 4. macOS Claude isolation — broken by upstream, but it is the package's *defining feature*

**Evidence:** `claude.py:390` carries a long comment: macOS Keychain entries are not scoped by `CLAUDE_CONFIG_DIR`, so a second Claude account on darwin overwrites the first. Tracked for 0.4.x.

**Why it matters:** "ai-accounts" — multiple accounts — is the name on the tin. Today on macOS that promise breaks for Claude.

**Recommendation (pick one):**
- Implement keychain swap-in/-out with an OS-level `fcntl.flock` on `~/.ai-accounts/claude.lock` (mentioned in the comment as racy — a real lock solves that).
- OR push users onto the cliproxyapi-managed flow exclusively on darwin (where credentials live in cliproxy's config dir, scoped by `auth-dir`).
- OR document the limitation in README, not just inline. It is currently invisible to anyone not reading source.

## 5. cliproxy/manager.py fragility — 579 LOC of upstream coupling

**Evidence:** `_DEVICE_CODE_RE` has been wrong twice; the SSRF port allowlist (`54545, 8085, 1455`) and callback-path allowlist (`/auth/callback`, `/callback`) need manual extension every cliproxy minor.

**Recommendation:** add a `cliproxy_compat.toml` listing version → {ports, paths, regexes}. Load by detected cliproxy version. Failures become "unsupported cliproxyapi version X" instead of silent regex misses.

## 6. README lists 4 backends but the Packages table only shows 3

`opencode` is fully implemented (`backends/opencode.py:451`, full test suite under `tests/backends/test_opencode_*.py`) but absent from the README backends section. Easy doc fix.

## 7. Tests not partitioned by domain consistently

`packages/core/tests/` mixes flat (`test_sqlite_storage.py`, `test_chat_events.py`, `test_domain.py`) with subdirs (`backends/`, `cliproxy/`, `storage/`, `pty/`, `install/`). Move flat ones into their respective subdirs for navigation.

## 8. Missing e2e for the headline use case

There is no test that drives a `mode=all` or `mode=compound` chat through the litestar route against fake backends end-to-end (only `test_chat_events.py` at the orchestrator level). The 0.3.9 / 0.3.10 / 0.3.12 chat regressions all escaped because the test pyramid is missing its top layer.

**Recommendation:** add `packages/litestar/tests/test_chat_send_e2e.py` using `pytest-httpx` and the existing `testing/fakes.py` to lock in the SSE shape.
